# История развития технологии

## Хранилище
%Repository %ForeignKey %RepositoryId %ActorId %RecordId %Database

%Repository %RepositoryId %ActorId %RecordId %Database
Прототип проекта Турбаза зародился после того, как я разработал приложение для организации семейных дел и осознал, что мне придется хранить данные других семей. Со временем возникла идея группировать данные в отдельные единицы знаний — хранилища. Каждое хранилище, с собственными ключом а также ключами  субъектов (Actor ID) и записей (Record ID), может охватывать любое количество стандартных реляционных таблиц.

%ForeignKey
Записи в одном хранилище могут ссылаться на записи в других хранилищах с помощью стандартных внешних ключей. Это делает хранилища взаимозависимыми. В то же время хранилища полностью автономны и хранят копии актуальных записей из других хранилищ, на которые они ссылаются (включая рекурсивные ссылки). Благодаря этому хранилища могут функционировать независимо и использоваться как самостоятельные единицы.

## Интерфейсы
%UI %Repository %Screen

В идеале пользовательские интерфейсы, отображающие содержимое хранилищ, должны выполнять первоначальную загрузку экрана для набора связанных записей, используя только то хранилище, к которому эти записи относятся, а также его копии записей, на которые имеются прямые ссылки из этого хранилища.

## Приложения
%App %Cooperation %Database %Join %API

%App %Cooperation %Database
Наряду с хранилищами сформировалась концепция взаимодействующих приложений. Приложения могут разрабатывать схемы баз данных для хранения своих данных. Их таблицы могут содержать внешние ключи, ссылающиеся на таблицы других приложений. Это обеспечивает взаимодействие приложений на уровне данных. Больше нет необходимости дублировать типы данных и концепции в разных приложениях; уже созданные стандартные типы данных можно использовать при разработке новых типов, предназначенных для конкретных задач.

%App %Cooperation %Join
Приложения могут считывать данные из схем других приложений и выполнять SQL-соединения (JOIN) для их объединения и связывания. 

%App %Cooperation %API
Чтобы записать данные в схему другого приложения помимо записи данных в собственную схему приложение должно обратиться к общественной оболочке того приложения, которому принадлежит целевая схема. Это способствует взаимодействию приложений на уровне бизнес-логики. Логика обработки определенных типов данных используется повторно вместе с самими типами данных. Приложения также могут вызывать логику извлечения данных, реализованную в других приложениях, получая тем самым доступ к уже обработанным данным.

## Хранилища и приложения
%Repository %App

Конкретное приложение создает конкретное хранилище, однако поддерживать одно хранилище могут несколько приложений. Таким образом, хранилище не привязано к приложению. Это отделяет приложение от обрабатываемых им данных, поскольку данные хранятся отдельно и принадлежат пользователям.

## Подача данных
%Tree

Идея о том, как именно следует складировать и подавать данные, окончательно сформировалась гораздо позже. Всегда было логичным что хранением общедоступных данных должны заниматься общественные организации. Кроме того, с самого начала возникла идея распределенного поиска данных с использованием хранилищ, поддерживающих индексацию и метаиндексацию. Однако лишь недавно стало очевидно, что для эффективного хранения и извлечения данных необходима древовидная серверная структура, поскольку большинство наших повседневных взаимодействий связано либо с местом нашего проживания, либо с темами и под-темами, представляющими для нас наибольший интерес.

## Извлечение данных
%Queue

Долгое время не было четкого понимания того, как именно следует эффективно извлекать записи. С появлением концепции древовидной структуры возникла идея использовать очереди с возможностью поиска для хранения недавно добавленных записей — предполагается что именно к ним пользователи будут обращаться чаще всего.

## Интернет
%Internet

Совсем недавно появилась концепция «интернета данных», призванного объединить независимые древовидные структуры — подобно тому, как в настоящем лесу подземные микоризы связывают между собой деревья и растения.
