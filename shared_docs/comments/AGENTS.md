# AGENTS.md — shared_docs/comments

## 🎯 Назначение и контекст (Purpose & Scope)
В этой директории собраны **личные авторские записи разработчика и создателя платформы «Турбаза»**, написанные **вручную человеком без использования искусственного интеллекта**.

Здесь зафиксированы:
- Первоначальные идеи, история зарождения и логика эволюции концепций платформы.
- Глубинная мотивация ключевых архитектурных решений (автономные хранилища, реляционные внешние ключи между хранилищами, отделение приложений от данных, древовидная топология, интернет данных).
- Семантически размеченные факты и принципы взаимодействия компонентов.

## 🏷️ Семантическая разметка (%Labels)
Для упрощения навигации и точного поиска фактов ИИ-агентами автор использует систему **семантических меток** (`%Label`), которые ставятся в начале параграфов или непосредственно под заголовками (см. [`LABELS.md`](file:///Users/parents/Documents/presentations/shared_docs/comments/LABELS.md)).

### Словарь ключевых меток:
| Метка | Понятие | Описание в контексте архитектуры |
|---|---|---|
| `%AccessRules` | Правила доступа | Проверка каркасом прав доступа приложений и ограничение записи только в собственную схему |
| `%Actor` | Субъект | Пользователь, использующий определенное приложение на определенном Листе |
| `%ActorId` | Ключ Субъекта | Идентификатор владельца / субъекта данных (пользователь + приложение + лист) |
| `%Analytics` | Аналитика | Агрегированный анализ дублируемой общественной информации на Ветвях и Стволе |
| `%API` | Общественная Оболочка | Публичный интерфейс приложения для безопасных межмодульных вызовов и записи данных |
| `%App` | Приложение | Программный модуль со своей схемой данных, отделенный от хранилища пользователя |
| `%Branch` | Ветка | Промежуточный узел агрегации (база публичных данных, долговременный архив, очередь, синхронизация) |
| `%Cache` | Кэш | Локальный кэш зашифрованных записей журналов изменений на Листе |
| `%ConcurrentMap` | Параллельная карта | Структура оперативной памяти на Ветке для изменений, еще не записанных в файловую систему |
| `%Connection` | Соединение | Связность узлов топологии (Лист $\leftrightarrow$ Ветка $\leftrightarrow$ Родительская Ветвь $\leftrightarrow$ Ствол) |
| `%Cooperation` | Взаимодействие | Механизмы взаимодействия приложений на уровне данных (FK, JOIN) и логики (API) |
| `%Database` | База Данных | Реляционные схемы таблиц с трёхколоночной структурой идентификаторов |
| `%Decorator` | Декоратор | Аннотации/маркировка методов и сущностей в библиотеках разработки приложений |
| `%Department` | Ведомство | Специализированные ведомственные ветви со сквозным защищенным доступом |
| `%DependencyInjection` | Внедрение зависимостей | Фреймворк внедрения зависимостей (DI) в библиотеках Турбазы для приложений |
| `%DisasterRecovery` | Аварийное восстановление | Узлы Ветвей и Ствола как реплики общественной информации для аварийного восстановления |
| `%Encryption` | Шифрование | Защита и сквозное шифрование записей журналов изменений хранилищ |
| `%Family` | Семья | Базовый субъект и целевая аудитория Турбазы; организация и обмен семейными данными |
| `%FileSystem` | Файловая система | Долгосрочное файловое хранилище журналов изменений хранилищ на Ветке |
| `%ForeignKey` | Внешние ключи | Составные ключи (`RepositoryId` + `ActorId` + `RecordId`) между автономными хранилищами |
| `%Framework` | Каркас | Исполняемая среда Листа: запуск SQL, контроль правил доступа, ведение журнала изменений |
| `%GenAI` | Генеративный ИИ | Использование отборных структурированных данных хранилищ для до-обучения ИИ-моделей |
| `%Group` | Группа | Закрытые сообщества и организации с «герметичными отсеками» данных |
| `%International` | Международный | Ствол как шлюз международного соединения и обмена данными |
| `%Internet` | Интернет | «Интернет данных» — объединение независимых древовидных структур подобно лесной микоризе |
| `%Join` | SQL-соединение | Чтение и объединение данных схем разных приложений напрямую через SQL JOIN |
| `%Leaf` | Лист | Периферийный суверенный узел древовидной структуры (устройства пользователей) |
| `%Libraries` | Библиотеки | Инструментальные библиотеки платформы (DI, ORM, декораторы, сборка пакетов API) |
| `%LLM` | Большая языковая модель | Обучение больших языковых моделей на децентрализованных репутационно размеченных данных |
| `%LongTermStorage` | Долгосрочное хранение | Надежный файловый архив журналов изменений хранилищ на узлах Ветки |
| `%Neighbors` | Соседи | Локальные приватные группы для добрососедского взаимодействия без публичной огласки |
| `%ORM` | Объектно-реляционное отображение | Инструменты ORM для удобной и безопасной работы приложений с таблицами БД |
| `%ParentBranch` | Родительская Ветвь | Вышестоящий агрегирующий связной узел иерархии веток |
| `%PassThroughСonnection` | Сквозное соединение | Сквозные защищенные каналы связи от Листа к ведомственным и внешним Ветвям |
| `%P2P` | Одноранговая сеть | Модули прямой передачи данных между Листами в обход промежуточных узлов |
| `%PersistentQueue` | Персистентная очередь | Быстрая очередь на Ветке для гарантированной фиксации входящих записей транзакций |
| `%PublicData` | Общественные данные | База общедоступных данных района/города, размещенная на Ветке |
| `%Queue` | Очередь | Очереди с возможностью поиска для быстрого извлечения недавно добавленных записей |
| `%RecordId` | Ключ Записи | Идентификатор конкретной записи внутри хранилища (локальная последовательность Листа) |
| `%Repository` | Хранилище | Единица знаний; охватывает реляционные таблицы, хранит актуальные копии внешних записей |
| `%RepositoryId` | Ключ Хранилища | Уникальный идентификатор хранилища |
| `%Screen` | Экран | Экран приложения и логика его первоначальной загрузки |
| `%Service` | Услуги | Ведомственные и профильные сервисы с разграничением прав доступа к данным граждан |
| `%SQL` | SQL | Реляционный язык запросов, безопасно исполняемый каркасом Листа |
| `%Synchronization` | Синхронизация | Модули репликации и согласования данных между Листами и Ветками (онлайн и оффлайн) |
| `%TransactionLog` | Журнал изменений | Журнал транзакций/изменений хранилищ с гарантированной фиксацией |
| `%Tree` | Дерево | Серверная древовидная структура для хранения и подачи данных по гео- и тематическому признаку |
| `%TreeSearch` | Обход дерева | Сводные древовидные поисковые индексы на Ветвях/Стволе для прямого поиска на Листах |
| `%Training` | Тренировка | Децентрализованное до-обучение и обучение ИИ на устройствах пользователей |
| `%Trunk` | Ствол | Корневой национальный и международный узел связности и аварийного восстановления |
| `%UI` | Интерфейс | Пользовательский интерфейс, загружающий экран из локального хранилища |
| `%User` | Пользователь | Владелец данных, независимый от приложений |

## 📋 Правила и инструкции для ИИ-агентов (Guidelines for AI Agents)

1. 🔒 **Строгий режим только для чтения (Read-Only):**
   - ИИ-агентам **запрещено** создавать, изменять или удалять файлы авторских заметок в директории `shared_docs/comments/` (за исключением файлов `AGENTS.md`).
   - Эти записи являются неизменяемым историческим первоисточником мыслей разработчика.

2. 🧠 **Первоисточник архитектурного замысла (Source of Author Intent):**
   - При подготовке презентаций, слайдов, пояснительных записок и технической документации агент обязан опираться на эти записи для точной передачи терминологии и философии платформы.
   - Особое внимание обращать на фундаментальные принципы: *отделение приложений от данных*, *суверенитет хранилищ при сохранении внешних связей*, *микоризная сеть интернета данных*.

3. 🔍 **Использование семантических меток при поиске:**
   - При исследовании контекста используйте точечный поиск `grep_search` по меткам (например `Query: "%ForeignKey"`, `Query: "%Queue"`, `Query: "%API"`), чтобы находить параграфы с точной позицией разработчика.

4. 🔄 **Связывание с технической спецификацией:**
   - Сопоставляйте авторские заметки из `comments/` с формальными спецификациями в [`Технический документ платформы Турбаза.md`](file:///Users/parents/Documents/presentations/shared_docs/%D0%A2%D0%B5%D1%85%D0%BD%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B8%D0%B9%20%D0%B4%D0%BE%D0%BA%D1%83%D0%BC%D0%B5%D0%BD%D1%82%20%D0%BF%D0%BB%D0%B0%D1%82%D1%84%D0%BE%D1%80%D0%BC%D1%8B%20%D0%A2%D1%83%D1%80%D0%B1%D0%B0%D0%B7%D0%B0.md) для формирования целостной картины платформы.
