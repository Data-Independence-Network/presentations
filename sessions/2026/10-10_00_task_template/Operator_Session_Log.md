# Протокол сессии оператора: MM-DD_NN_Task_Name / Operator_Session_Log

> [!NOTE]
> **Канонический эталон протокола взаимодействия оператора в группе автономных сессий**  
> Настоящий документ ведётся моделью при интерактивном диалоге с оператором внутри пакета задач `sessions/2026/MM-DD_NN_[Название_задачи]/`.  
> 
> **Двухфазный жизненный цикл сессии оператора:**  
> 1. **Фаза проектирования мастер-плана:** модель опрашивает оператора через интервью / серию интервью, выявляет все детали задачи, формирует [Overall_Plan.md](./Overall_Plan.md) и регистрирует ссылку на него в [Current_Topic_and_process.md](../../Current_Topic_and_process.md).  
> 2. **Фаза формирования автономных планов (в той же сессии):** на базе мастер-плана модель разрабатывает детальные планы [Session_0X_Plan.md](./Session_01_Plan.md) и чеклисты [Session_0X_Checklist.md](./Session_01_Checklist.md) со сгруппированными списками задач, назначая конкретные модели на каждую ступень.  
> 
> **Ключевой инвариант автономного пакета:** каждый завершённый обмен между оператором и моделью (каждый диалоговый шаг) **обязательно фиксируется коммитом в Git** вместе со всеми созданными или модифицированными файлами. Это обеспечивает строгую хронологическую привязку директив оператора к результатам автономных шагов.

## 3. Регламентные принципы и инварианты сессии оператора
1. **Интервьюирование оператора для создания мастер-плана:**
   - Модель начинает с вопроса оператору о том, какой план нужен.
   - Задаёт структурированные вопросы или проводит серию интервью для выяснения целей, архитектурных рамок, зависимостей и критериев приёмки.
   - Формирует [Overall_Plan.md](./Overall_Plan.md) и прописывает ссылку на него в [Current_Topic_and_process.md](../../Current_Topic_and_process.md).
2. **Формирование детальных планов автономных сессий (в той же сессии):**
   - На основе согласованного мастер-плана модель формирует файлы [Session_0X_Plan.md](./Session_01_Plan.md) и [Session_0X_Checklist.md](./Session_01_Checklist.md).
   - При необходимости модель проводит дополнительное интервью для уточнения состава дел и специфики конкретной ступени.
   - В планах прописываются сгруппированные списки дел с обязательным Git-коммитом в конце каждой группы.
   - На каждую ступень назначается конкретная модель-исполнитель с инструкцией фиксировать атрибуцию в артефактах.
3. **Непрерывная фиксация каждого диалогового шага в Git:**
   - Каждый шаг диалога с оператором завершается обязательным коммитом в Git (`git add <файлы> && git commit -m "..."`).
   - Сообщение коммита строится по правилу: `docs(session): MM-DD_NN шаг K — краткое описание действия оператора`.
   - В блоке шага фиксируются хэш коммита, перечень сохранённых файлов и статус привязки.
4. **Инвариант относительной навигации:**
   - Все ссылки строятся строго локально относительно расположения файла (`./`, `../`, `../../`).
5. **Курирование статусов и маркировки завершения:**
   - По завершении автономных ступеней проверяется маркировка `[x]` в [Overall_Plan.md](./Overall_Plan.md) для исключения повторного запуска пройденных этапов.
