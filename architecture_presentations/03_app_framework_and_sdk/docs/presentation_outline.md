## 🧭 Послайдовая структура (15 слайдов)

1. **Слайд 01: Титульный слайд — Каркас приложений и SDK Турбазы**
   - Назначение: Манифест прикладного слоя платформы: создание распределенного софта без бэкенда, облачных БД и DevOps-затрат.
   - Визуальный чертеж: Стековая архитектура (UI-слой $\to$ Фреймворк $\to$ Песочница $\to$ Движок Турбазы $\to$ SQLite).

2. **Слайд 02: Архитектура компилятора Runway: Нулевые декораторы в рантайме**
   - Инженерия: Декларативные декораторы TypeScript (`@Entity()`, `@Table()`, `@Id()`, `@ManyToOne()`) как маркеры статического анализа.
   - Оптимизация: Полное исключение рантайм-рефлексии (`reflect-metadata`), компиляция в строго типизированные AST, сущности `QEntity` и базовые DAO.

3. **Слайд 03: Архитектура песочницы (Sandbox): Изоляция контекстов**
   - Угроза: Уязвимости XSS и перекрестное чтение памяти при одновременном запуске десятков независимых приложений в одном браузере.
   - Защита: Изоляция приложений в доменных IFrame с рандомизацией поддоменов и строгим блокированием прямого доступа к DOM и хранилищам ядра.

4. **Слайд 04: Межконтекстный RPC: Надежный обмен через postMessage**
   - Протокол: Асинхронный обмен сообщениями между окном приложения и системным ядром Турбазы через `window.postMessage`.
   - Защита: Пакетный дебаунсинг (debouncing), уникальные токены запросов (Request Correlation ID) и защита от спама шины вызовов.

5. **Слайд 05: Принцип «Read-Anywhere, Write-Self»: Архитектурный манифест**
   - Философия: Фундаментальный закон безопасности данных в «Турбазе».
   - Суть принципа: Любое доверенное приложение может читать любые локальные данные пользователя, но изменять чужие сущности имеет право только приложение-владелец.

6. **Слайд 06: Реализация «Read-Anywhere»: Прозрачные кросс-схемные SQL SELECT**
   - Инженерия: Прямое выполнение SQL-запросов с операторами `JOIN` между таблицами разных вендоров на едином ядре SQLite.
   - Кейс: Органайзер «Деловой» объединяет в одном представлении задачи из CRM, трекинг билетов из «УраТур» и локальные контакты без API-шлюзов.

7. **Слайд 07: Реализация «Write-Self»: Перехват графа и маркер FROM_ANOTHER_APP**
   - Механизм защиты: Инспекция графа модификаций в `EntityGraphReconstructor`.
   - Блокировка: Сущности чужих схем помечаются маркером `FROM_ANOTHER_APP` и принудительно исключаются из очередей записи в `DependencyGraphResolver`.

8. **Слайд 08: Общественные интерфейсы (@Api()): Легитимный путь мутаций**
   - Паттерн: Декоратор `@Api()` как контракт открытого интерфейса микросервиса.
   - Процесс: Для изменения чужой сущности приложение вызывает экспортированный API-метод владельца, выполняющий валидацию бизнес-правил.

9. **Слайд 09: Контекстный Dependency Injection (direction-indicator)**
   - Архитектура: Легковесный DI-контейнер без тяжелых фреймворков (Spring / NestJS).
   - Инженерия: Разрешение зависимостей на лету через дескрипторы свойств `Object.defineProperty` с привязкой к контексту транзакции.

10. **Слайд 10: Типизированный построитель запросов (Tarmaq DSL)**
    - Возможности: Типобезопасный SQL-DSL на TypeScript: сгенерированные `QEntity`, предикаты `equals()`, `isIn()`, операторы `LEFT_JOIN()`.
    - Безопасность: Полная защита от SQL-инъекций на этапе компиляции без потери гибкости сложных агрегатных запросов.

11. **Слайд 11: Реактивные DAO с живыми запросами (Live Queries)**
    - Механика: Метод `Dao._search()` регистрирует реактивную подписку на таблицы SQLite.
    - Реактивность: Автоматическая трансляция фиксаций в WAL в потоки RxJS `Observable` — интерфейс мгновенно обновляется без ручного поллинга.

12. **Слайд 12: Эволюция моделей данных: Миграции без даунтайма**
    - Проблема: Как обновлять схемы таблиц на миллионах автономных устройств пользователей без центрального администратора.
    - Решение: Версионирование DDL, атомарная инъекция патчей схем при старте новой версии приложения и обратная совместимость представлений.

13. **Слайд 13: Жизненный цикл сервиса и дистрибуция**
    - Конвейер: Сборка пакетов приложений, верификация открытого ключа разработчика, публикация деклараций схем и локальное развертывание.
    - Доверие: Полная прозрачность исходного кода и отсутствие скрытых сетевых коннекторов.

14. **Слайд 14: Интеграция пользовательского интерфейса: Прямая связь со Signals**
    - Архитектура UI: Мост от RxJS `Observable` к современным реактивным примитивам Angular Signals (`toSignal()`) и React Hooks.
    - Производительность: Гранулярный рендеринг компонентов с нулевым сетевым оверхедом и откликом в 1 кадр дисплея (16 мс / 60 FPS).

15. **Слайд 15: Архитектурное резюме для инженера**
    - Итог: Framework и SDK Турбазы как готовый промышленный стек для создания автономного отечественного ПО с прямым владением информацией.
    - Экономический эффект: Снижение затрат на разработку бэкенда на 100% и нулевые счета за облачные СУБД.
