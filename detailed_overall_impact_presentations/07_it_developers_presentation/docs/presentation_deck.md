### Текст для диктора:
> Каждый программист и основатель стартапа знает, насколько тяжело сегодня запустить независимый продукт.
>
> Вместо того чтобы писать логику приложения, восемьдесят процентов времени уходит на настройку инфраструктуры: сервера, базы данных, докер-контейнеры и постоянную борьбу с багами сетевого взаимодействия.
>
> При этом облачные счета растут с каждым новым пользователем, угрожая разорить проект еще на стадии роста.
>
> А если проект публикуется в мобильных сторах, корпорации накладывают тридцатипроцентный оброк и в любой момент могут удалить приложение из каталога по надуманным причинам.
>
> В то же время открытый исходный код безжалостно эксплуатируется бигтехом без какого-либо вознаграждения авторам.
>
> Турбаза ломает эту несправедливую систему.

### Текст для диктора:
> Как устроена разработка в концепции True Serverless Edge?
>
> Вместо аренды виртуальных машин в облаках вы компилируете свой код в компактные модули, которые исполняются прямо на смартфонах пользователей в защищенных песочницах.
>
> Приложение работает с локальной базой данных SQLite: запросы выполняются со скоростью микросекунд, без задержек на передачу по сети.
>
> Это полностью меняет экономику проекта: масштабирование становится абсолютно бесплатным.
>
> Приход миллиона новых пользователей больше не грозит падением серверов — каждый пользователь сам предоставляет процессор и память для работы своего приложения.
>
> А благодаря принципу конструктора Лего вы можете собирать готовые сервисы из открытых модулей других авторов всего за пару дней.

### Текст для диктора:
> Как устроена экономика API в платформе Турбаза?
>
> Мы реализовали математически выверенную модель разделения доходов на базе теории игр.
>
> Когда приложение генерирует доход — будь то показ рекламы или прямая оплата услуг пользователем — система анализирует криптографический след вызова.
>
> Доход делится на эн равных частей между всеми создателями задействованных компонентов.
>
> Если в приложении использован визуальный интерфейс одного автора, алгоритм расчета другого инженера и реляционная схема данных третьего разработчика — каждый из них автоматически получает ровно одну треть от пула вознаграждения.
>
> Это гарантирует, что труд создателей открытых библиотек и качественных схем данных наконец-то получает достойную финансовую оценку.
